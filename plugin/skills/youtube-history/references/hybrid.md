# Hybrid synchronization

- First invocation: verify the user-selected account and private DB; import any new completed history-only Takeout archive. Never automatically initiate a full export for this event.
- Full baseline: use the provider's recurring Takeout option every two months for one year, if the user chooses to configure it directly on Google. Do not claim that the schedule is active without provider confirmation. Do not bypass MFA.
- Recent update: query a supported authorized recent-activity source for the interval reported by `incremental.py plan`. Use precise timestamps, explicit watch/search event and platform, title and verified YouTube URL. If no permitted source provides these, use the latest snapshot and report missing interval. The tool does not itself fetch Google remotely.
- Local commands: `python incremental.py --db history.sqlite --account-label MY-ACCOUNT bind` (empty DB), or `bind-existing` after verifying ownership; `plan`; `import recent.json`. Use a separate DB and inbox for every account. The label is a user-selected identifier, not Google authentication. Do not put credentials in the label. The initial recent window is 14 days; subsequent verified windows overlap by at least 2 days. Partial batches are imported but cannot advance the completion checkpoint.
- Batch JSON: `account_key` from plan, `source` = `authorized_recent_activity` or `owner_export`, `from`, `through` (ISO timestamps with offsets), `complete` boolean, `events` list `{kind,platform,title,url,time,channel}`. Mark complete only when actual full interval traversal is established; not from page maximum date or lack of results. Keep unknowns explicit; do not synthesize URLs/dates.
- Rotation: follow rotation.md and verify complete snapshot coverage and provenance before the account owner manually disposes of redundant copies. Never remove native history or unrelated archives.
- Storage: no server or background process is bundled. First invocation can orchestrate available tools, but if the runtime cannot run code or persist a DB, report the limitation. Google can still require periodic authentication.
