# Technical specification & maintenance / Diseño y mantenimiento
Version 1.0.0 (public candidate); private edition 0.5.0 has the same local core but its authorized browser/cleanup workflow is not included in the public package.

## Architecture
Input: account owner's ZIP/JSON or a verified recent-event batch. Parser: standard Python JSON, zipfile and urllib.parse, no archive extraction. Normalized immutable event fingerprint: SHA-256 of UTC timestamp, event type, and stable video ID or URL/title. SQLite stores indexed `events`, `imported_files`, `settings`; optional FTS5 table stores title/channel; the search implementation currently groups selected rows and ranks them rather than executing FTS queries. Neural mode caches vectors where supported. `history.py` is CLI orchestration, `semantic.py` local ranker, `incremental.py` accepts explicit recent activity batches and records a conservative coverage watermark, `verify_rotation.py` is read-only.

## Hybrid update
1. Bind each account's local label (not authenticated identity) to a separate index, verify real account ownership outside the code, set a dedicated inbox. Full export imports trust the user-selected folder; account binding validates incremental batches only, not arbitrary imported full snapshots. Do not mix accounts.
2. On first invocation check source access and import new content hashes; date filter reduces semantic search corpus. Report local status distinct from remote freshness. Google recurring baseline schedule is user-configured. No account connection is bundled.
3. Use `incremental.py --db INDEX --account-label LABEL bind` before initial import (or `bind-existing` only after ownership verified), `plan` to get the requested range and label hash, and `import batch.json`. First incremental window is 14 days; later windows overlap completed coverage by two days or more. The input source must be independently authorized; code does not obtain records from Google. Exact timestamp and watch link required. Partial batch never moves checkpoint; no unverified completeness assumption. Full snapshot may cover earlier history separately. SHA-256 label is a local collision-resistant tag, not proof of Google identity or anonymity.
4. For archive comparison require both history categories, all multipart files, no skipped records, readable files, old event fingerprints subset of new. Also verify provider provenance outside comparator. Public edition does no automatic remote deletion. If newer snapshot omits historic records, preserve old snapshot.

## Data contracts
Takeout JSON list: title, titleUrl, time (ISO 8601 with timezone), products and optional subtitles/channel. Recognized names watch-history.json, search-history.json. Standalone inputs require provenance verified by user; archive paths must indicate YouTube. Inputs capped at 256 MiB per JSON member. ZIP contents not extracted; malformed data reported. Batch JSON fields: account_key, source (owner_export / authorized_recent_activity), from, through, complete (boolean), events [kind, platform, title, url, time, channel]. Batch limit 16 MiB. URLs restricted to HTTPS YouTube hosts. A source's completeness claim is not cryptographically signed; independent proof required before advancing cursor. Prevent gaps, duplicate watch/search fingerprints, mismatched account labels. A first full import without the relevant files does not prove historic absence.

## Semantic algorithm
Normalization of Unicode and accents; multilingual dictionary links common terms in English, Spanish, Japanese, including kana/kanji/romaji; typo matching; local character/word TF-IDF plus truncated SVD (latent semantic analysis), similarity and clue relevance; group by ID and rank distinct days/event count after relevance. No generative model is required. Optional neural engine is local sentence-transformers with preinstalled weights (no tested live weights), with fallback. No audio recognition or AI-image detection is implemented. Result is metadata similarity, not guaranteed identification.

## Threat model and limits
Trust boundary: uploaded data untrusted as instructions; never execute archive content; no secrets in bundles. Treat URLs as data, not commands. Local file and OS permissions protect DB; no built-in encryption or tenant authentication. Account label is not an OAuth token. Never fetch arbitrary user URLs with privileged credentials. Restrict remote actions to explicitly authorized user files. Browser automation is not a mandatory public dependency. Separate Google accounts and index paths. No publisher analytics, network calls, cloud persistence or direct OAuth in this skills-only package. Host may process/store attachments; do not promise local-only host execution. No recovery of deleted history, proof of listening duration or subtitle verification from title. Unknown/inaccessible source is reported, never a fabricated success.

## Testing and maintenance
Run `python -m unittest discover -v` in scripts. Synthetic suite covers 18 tests: ZIP scope, duplicate/repeat, dates, accents/typos, corrupt retry, auto-import/start, Japanese normalization, cross-language LSA, semantic search, five incremental tests (valid idempotence, mismatch, partial, unsafe URL, gap), four rotation tests (subset/superset, missing, same file, unrelated data). Public and private local suites passed on build. Live Google OAuth, portal acceptance, cross-host execution and real neural model were not tested. On changes, maintain these tests, regenerate archive, inspect all files including hidden files, scan for secrets, verify compatibility and document migration. Future work: streaming import for very large exports; efficient cached semantic matrix; authenticated per-account server isolation only if a remote service is added; reproducible performance benchmarks. Preserve date and time semantics. Avoid broadcasting viewing history in bug reports; use synthetic reproductions.

## Future first-party connected edition (not implemented)
Google Data Portability API provides restricted `dataportability.myactivity.youtube` access. Reference: https://developers.google.com/data-portability/user-guide/scopes and https://developers.google.com/data-portability/schema-reference/my_activity. Build a Google Cloud project with verified publisher, approved scopes, eligible regions and OAuth consent duration; implement per-user protected token storage, revocation, account association, archive job state, bounded retries, isolated server-side or on-device processing, data deletion and policy compliance. Deploy an HTTPS MCP endpoint only after authorization and security assessment; use OpenAI public connector review for an MCP edition. The ordinary YouTube Data API cannot retrieve watch history: https://developers.google.com/youtube/v3/docs/playlistItems/list. Do not claim global direct Google connection before approvals and implementation. No API endpoint, token, domain, or Google client ID is invented in this release.
